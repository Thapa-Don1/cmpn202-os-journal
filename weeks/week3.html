📊 Application Selection Matrix

Five applications selected to represent distinct workload types, ensuring comprehensive coverage of OS resource management behaviours.

Application Workload Type Justification Key Metrics
stress-ng CPU-Intensive Industry standard stress testing tool. Generates controlled CPU load to test scheduler behaviour and thermal performance. CPU %, load average, temperature
sysbench RAM-Intensive Benchmarks memory throughput and latency. Reveals how the OS manages memory allocation under pressure. Memory bandwidth, latency, page faults
fio I/O-Intensive Flexible I/O tester that simulates real disk workloads. Tests sequential and random read/write performance. IOPS, throughput MB/s, latency ms
iperf3 Network-Intensive Measures network throughput between workstation and server. Tests TCP/UDP bandwidth and connection quality. Throughput Mbps, jitter, packet loss
nginx Server Application Production-grade web server representing real service workloads. Tests response time under concurrent connections. Requests/sec, response time, connections

🔍 Monitoring Strategy

Measurement approach for each application — all monitoring performed remotely via SSH.

stress-ng — CPU Monitoring Use top -bn1 and mpstat 1 10 to capture per-core utilisation. Record load average from uptime before, during, and after stress test.
sysbench — Memory Monitoring Use free -h and vmstat 1 10 to track memory allocation. sysbench outputs its own MB/s throughput results directly.
fio — Disk I/O Monitoring Use iostat -x 1 10 to capture IOPS and throughput. fio generates detailed output including read/write speeds and latency percentiles.
iperf3 — Network Monitoring Run iperf3 server on Ubuntu VM, client on Windows host. Captures bidirectional throughput in Mbps automatically.
nginx — Service Monitoring Use ab (Apache Benchmark) from Windows to send concurrent requests. Monitor with ss -s for connections and top for CPU during load.
Baseline — All Tests Record free -h, top -bn1, df -h, and uptime before every test run to establish a clean baseline for comparison.

📝 Week 3 Reflection

The choice of applications was based on the necessity to measure separately the efficiency of such subsystems as the CPU scheduler, memory management, I/O, and networking. Due to the fact that the selected applications will put a stress on one resource, we can understand how Ubuntu 26.04 handles them.


Inclusion of nginx among the applications is needed since it introduces different types of loads on the operating system (CPU, memory, networking), which resembles production-like use.


Key decision: stress-ng over the outdated stress due to greater granularity and possibility to analyse the results more effectively and thoroughly.
