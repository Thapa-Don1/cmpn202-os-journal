🔬 Testing Methodology

All tests executed remotely via SSH from the Windows workstation. Each test follows the same structured approach for consistency.

Step 1 — Record Baseline Capture CPU, memory, disk, and network metrics with zero load. This is the reference point for all comparisons.
Step 2 — Apply Load Run each application at defined intensity. Record metrics every 5 seconds during the test.
Step 3 — Identify Bottleneck Determine which resource (CPU, RAM, disk, network) becomes the limiting factor under each workload.
Step 4 — Optimise and Re-test Apply at least two improvements and re-measure to quantify the impact with before/after data.

⚡ Optimisation Analysis

Minimum two optimisations implemented and measured with before/after quantitative data.

Optimisation 1 — nginx Worker Process Tuning

By default nginx uses 1 worker process. Setting it to match CPU core count improves throughput.

ubuntu@server:~$ nproc
2
ubuntu@server:~$ sudo nano /etc/nginx/nginx.conf
# Change: worker_processes 1;
# To:     worker_processes 2;
MetricBeforeAfterImprovement
Requests/second[BEFORE][AFTER][% change]
Mean response time[BEFORE] ms[AFTER] ms[% change]

Optimisation 2 — Swappiness Tuning

Default swappiness of 60 causes the kernel to swap memory aggressively. Reducing it keeps more data in RAM for server workloads.

ubuntu@server:~$ cat /proc/sys/vm/swappiness
60
ubuntu@server:~$ sudo sysctl vm.swappiness=10
ubuntu@server:~$ sudo nano /etc/sysctl.conf
# Add: vm.swappiness=10
