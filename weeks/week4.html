🔑 SSH Key-Based Authentication

Replacing password authentication with cryptographic key pairs — industry standard for secure server access.

Step 1 — Generate SSH keypair on Windows workstation

Run in Windows PowerShell (not on the server):

PS C:\Users\spraj> ssh-keygen -t ed25519 -C "cmpn202-coursework"
Generating public/private ed25519 key pair.
Enter file in which to save the key (C:\Users\spraj/.ssh/id_ed25519):
Enter passphrase (empty for no passphrase):
Your identification has been saved in C:\Users\spraj/.ssh/id_ed25519
Your public key has been saved in C:\Users\spraj/.ssh/id_ed25519.pub
The key fingerprint is:
SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx cmpn202-coursework

Step 2 — Copy public key to server

From Windows PowerShell:

PS C:\Users\spraj> type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh ubuntu@192.168.1.66 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys && chmod 700 ~/.ssh"

Step 3 — Test key-based login

PS C:\Users\spraj> ssh ubuntu@192.168.1.66
Welcome to Ubuntu 26.04 LTS (GNU/Linux 7.0.0-15-generic x86_64)
ubuntu@server:~$
# No password prompt — key authentication successful

Step 4 — Disable password authentication on server

Edit SSH config via SSH session:

ubuntu@server:~$ sudo nano /etc/ssh/sshd_config

Before — sshd_config (relevant lines)

# Before changes
PasswordAuthentication yes
PermitRootLogin yes
PubkeyAuthentication yes

After — sshd_config (hardened)

# After hardening
PasswordAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
AllowUsers ubuntu

Step 5 — Restart SSH service

ubuntu@server:~$ sudo systemctl restart ssh
ubuntu@server:~$ sudo systemctl status ssh
● ssh.service - OpenBSD Secure Shell server
     Loaded: loaded (/usr/lib/systemd/system/ssh.service; enabled)
     Active: active (running)
📸 Evidence needed: Replace text blocks above with screenshots from your actual SSH session showing each step. Most importantly capture the successful key-based login with no password prompt.
Security outcome: Password-based SSH login is now completely disabled. Only the Windows workstation holding the private key can authenticate. Brute force password attacks are no longer possible.

🔥 Firewall Configuration (UFW)

Configuring UFW (Uncomplicated Firewall) to deny all incoming traffic except SSH from the workstation IP only.

Step 1 — Check UFW status

ubuntu@server:~$ sudo ufw status
Status: inactive

Step 2 — Set default policies

ubuntu@server:~$ sudo ufw default deny incoming
Default incoming policy changed to 'deny'
ubuntu@server:~$ sudo ufw default allow outgoing
Default outgoing policy changed to 'allow'

Step 3 — Allow SSH from workstation IP only

ubuntu@server:~$ sudo ufw allow from 192.168.1.0/24 to any port 22
Rule added

Step 4 — Enable firewall

ubuntu@server:~$ sudo ufw enable
Command may disrupt existing ssh connections. Proceed with operation (y|n)? y
Firewall is active and enabled on system startup

Step 5 — Verify complete ruleset

ubuntu@server:~$ sudo ufw status verbose
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
New profiles: skip

To                         Action      From
--                         ------      ----
22                         ALLOW IN    192.168.1.0/24
📸 Evidence needed: Screenshot the UFW status verbose output showing your actual firewall rules. This is a mandatory deliverable.
Security outcome: All incoming connections are blocked by default. Only SSH connections from the local network subnet (192.168.1.0/24) are permitted. Every other port and protocol is denied.

👤 User & Privilege Management

Verifying and documenting the non-root administrative user configuration.

Verify current user and groups

ubuntu@server:~$ whoami
ubuntu

uid=1000(ubuntu) gid=1000(ubuntu) groups=1000(ubuntu),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev)
ubuntu@server:~$ sudo -l
Matching Defaults entries for ubuntu on server:
    env_reset, mail_badpass
User ubuntu may run the following commands on server:
    (ALL : ALL) ALL

Check no other users have sudo access

ubuntu@server:~$ getent group sudo
sudo:x:27:ubuntu

Verify root login is disabled

ubuntu@server:~$ sudo passwd -l root
passwd: password expiry information changed.
ubuntu@server:~$ sudo passwd -S root
root L 05/21/2026 0 99999 7 -1
User management summary: Single non-root user 'ubuntu' with sudo privileges. Root account is locked. Only one user has sudo access. This follows the principle of least privilege.

📝 Week 4 Reflection

This week marked the transition from planning to implementation. Configuring SSH key-based authentication required careful sequencing — the key must be copied to the server before disabling password authentication, otherwise you lock yourself out permanently.


The UFW firewall configuration highlighted an important trade-off: restricting SSH to only the workstation subnet (192.168.1.0/24) significantly reduces attack surface but means the server cannot be accessed from any other location. This is acceptable for a coursework environment but would require a VPN solution in production.


Key learning: The order of operations in security configuration matters critically. Enabling the firewall before confirming SSH rules could have blocked all access. Testing each step before proceeding is essential professional practice.
