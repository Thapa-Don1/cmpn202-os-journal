🔍 Lynis Security Audit

Lynis is an open-source security auditing tool that scans the system and produces a hardening index score with specific recommendations.

Step 1 — Install Lynis

ubuntu@server:~$ sudo apt install lynis -y

🔧 Lynis Remediation Steps

Actions taken to address Lynis warnings and improve the hardening index score.

Common remediation — Install malware scanner

ubuntu@server:~$ sudo apt install rkhunter -y
ubuntu@server:~$ sudo rkhunter --update
ubuntu@server:~$ sudo rkhunter --check --skip-keypress

Common remediation — Secure shared memory

ubuntu@server:~$ sudo nano /etc/fstab
# Add this line:
tmpfs /run/shm tmpfs defaults,noexec,nosuid 0 0
ubuntu@server:~$ sudo mount -a

Common remediation — Set login banner

ubuntu@server:~$ sudo nano /etc/issue.net
# Add warning banner:
Authorised users only. All activity may be monitored and reported.

ubuntu@server:~$ sudo nano /etc/ssh/sshd_config
# Add: Banner /etc/issue.net
ubuntu@server:~$ sudo systemctl restart ssh

Common remediation — Harden sysctl settings

ubuntu@server:~$ sudo nano /etc/sysctl.conf
# Add hardening settings:
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.rp_filter = 1
kernel.dmesg_restrict = 1

ubuntu@server:~$ sudo sysctl -p

Step — Re-run Lynis after remediation

ubuntu@server:~$ sudo lynis audit system
  Hardening index : [IMPROVED SCORE] [######################]
Target: Aim for a Lynis hardening index above 80. Document every remediation step with the specific Lynis warning it addresses.

🗺️ nmap Network Security Assessment

nmap scans the server from the workstation perspective to identify open ports and exposed services — exactly what an attacker would see.

Step 1 — Install nmap on Windows workstation

Download from nmap.org and install on Windows. Then run from PowerShell:

Step 2 — Basic port scan

PS C:\Users\spraj> nmap 192.168.1.66
Starting Nmap scan...
PORT   STATE SERVICE
22/tcp open  ssh

Nmap done: 1 IP address (1 host up) scanned

Step 3 — Detailed service version scan

PS C:\Users\spraj> nmap -sV -sC 192.168.1.66
Starting Nmap scan...
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 9.x Ubuntu

Service detection performed.

Step 4 — Check for all ports

PS C:\Users\spraj> nmap -p- 192.168.1.66
Starting Nmap scan...
PORT   STATE SERVICE
22/tcp open  ssh

All other ports: filtered/closed
PortStateServiceJustification
22/tcpOpenSSHRequired for remote administration — restricted to local subnet
80/tcpFiltered/ClosedHTTPnginx running but blocked by UFW — only opened during testing
All othersFilteredN/ABlocked by UFW default deny incoming policy
nmap finding: Only port 22 (SSH) is visible externally. All other ports are filtered by UFW. This confirms the firewall is functioning correctly and minimises attack surface.

⚠️ Remaining Risk Assessment

Honest assessment of residual risks that remain despite implemented controls.

RiskLikelihoodImpactMitigation Status
SSH private key compromise on workstation Low High ⚠️ Partial — key has no passphrase set. Recommend adding passphrase.
Zero-day vulnerability in OpenSSH Very Low Critical ⚠️ Mitigated by auto-updates but cannot be fully eliminated
VM escape from VirtualBox Very Low Critical ✅ Acceptable — VirtualBox is regularly updated, host is isolated
Bridged network exposes VM to LAN Low Medium ⚠️ UFW mitigates but host-only would be more isolated
Unmonitored cron jobs Low Medium ✅ Mitigated — crontab reviewed, only system jobs present

📋 Final Security Report Summary

SSH Security Key-based authentication enabled. Password auth disabled. Root login prohibited. AllowUsers restricts access to ubuntu only.
Firewall UFW active with default deny incoming. Only port 22 open, restricted to local subnet. All other ports filtered.
Intrusion Detection fail2ban monitoring SSH with 3-attempt ban threshold. Automatic 1-hour bans applied to offending IPs.
Mandatory Access Control AppArmor running with 35 profiles in enforce mode. nginx profile enforced to limit service permissions.
Patch Management Automatic security updates enabled via unattended-upgrades. Security patches applied within 24 hours of release.
Lynis Score Hardening index improved from [BEFORE] to [AFTER] through systematic remediation of identified warnings.
Overall assessment: The system implements defence-in-depth with five independent security layers. Each control provides protection independently — if one fails, others remain effective. The attack surface is minimal with only SSH exposed and restricted to the local subnet.
