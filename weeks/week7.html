🔧 Lynis Remediation Steps

Steps taken to address Lynis suggestions and improve the hardening index.

Remediation 1 — Install rkhunter malware scanner

ubuntu@server:~$ sudo apt install rkhunter -y

Remediation 2 — Harden sysctl network settings

ubuntu@server:~$ sudo nano /etc/sysctl.conf
# Added:
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.rp_filter = 1
kernel.dmesg_restrict = 1

ubuntu@server:~$ sudo sysctl -p

Remediation 3 — Set SSH login banner

ubuntu@server:~$ echo "Authorised users only. All activity is monitored." | sudo tee /etc/issue.net
ubuntu@server:~$ echo "Banner /etc/issue.net" | sudo tee -a /etc/ssh/sshd_config
ubuntu@server:~$ sudo systemctl restart ssh
Remediation outcome: Three specific Lynis suggestions addressed. Score improved from 66 to 68. Remaining suggestions require enterprise tools or configuration changes beyond the scope of this coursework environment.

📋 Final Security Report Summary

SSH Security Key-based auth enabled. Password auth disabled. Root login prohibited. AllowUsers restricts to ubuntu only. Login banner set.
Firewall (UFW) Default deny incoming. Only port 22 open restricted to 192.168.1.0/24. Confirmed by nmap — 999 ports filtered.
Intrusion Detection fail2ban active with SSH jail. 3-attempt ban threshold. 1-hour automatic bans. Zero bans during coursework.
Access Control AppArmor running with 126 profiles enforcing. Provides mandatory access control for all confined services.
Patch Management Unattended-upgrades enabled. Security patches applied automatically within 24 hours of release.
Lynis Score Improved from 66 to 68 through systematic remediation. sysctl hardening, rkhunter, and login banner added.
Overall assessment: Defence-in-depth implemented with five independent security layers. 13/13 baseline checks passing. Attack surface minimal — only SSH exposed, restricted to local subnet, protected by key auth and fail2ban.

📝 Week 7 Reflection & Overall Conclusions

Lynis audit gave us an objective metric for security hardening, with an initial score of 66 which indicated very good security already implemented in Weeks 4 and 5. However, the score could have been improved due to Ubuntu 26.04 not being included in the EOL list of Lynis yet — this was mentioned as a notice, not a warning. Sysctl hardening, installation of rkhunter and SSH login banner helped increase the score to 68.


Nmap scan demonstrated that the firewall is working as intended — only port 22 is open from outside, with all other ports being filtered. Moreover, first nmap scan results showed "host seems down" even without -Pn option, thus indicating that UFW can block even ICMP ping probe. It is an even greater level of security than assignment required.


Key learning across 7 weeks: There is genuine conflict between security and performance. While both of these systems are needed and important, we can see that such solutions as AppArmor and fail2ban have some overhead, though testing done in Week 6 proved that it is insignificant for our baseline CPUs.


Employability reflection: The skills I learned during this assignment course, including SSH administration, firewall setup, shell scripting, benchmarking, and auditing, all correspond directly to the work carried out on a day-to-day basis by cloud engineers, DevOps engineers, and security experts. Ubuntu Server running SSH only is exactly how AWS EC2, Azure Virtual Machines, and Google Cloud instances are managed in production environments.
